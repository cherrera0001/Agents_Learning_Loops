3. El Workflow Operativo Paso a Paso

Fase 0 · Triage y Estimación por Tallas
Rol: Orquestador · Entorno: GitHub Projects

Se evalúa el issue según los 4 factores canónicos: Alcance (A), Incertidumbre (I), Riesgo (R) y Verificación (V). Se asigna la talla (XS a XL) que define el presupuesto $k_{\max}$ de iteraciones y enruta la capacidad.

Fase 1 · Arnés de Experimento & Recuperación Mnemotécnica
Componente: Arnés SWE-bench + MemoryGraph

El arnés clona el repositorio bajo prueba en un sandbox aislado y aplica la frontera de fuga (oculta tests privados). Se consulta la memoria: si existe una Skill activa para este síntoma, se ejecuta en 1 paso ($k=1$); si no, se dispara activación propagada (Collins & Loftus) desde la traza de excepción cruda y los símbolos del AST.

Fase 2 · El Bucle Acotado de ALL (Solver Gemma 4)
Máquina de estados: PLAN → RETRIEVE → ACT → OBSERVE

Gemma 4 formula una hipótesis de reparación y emite el parche git. El arnés ejecuta los tests de validación local y captura un recibo inmutable en evidence/.

Fase 3 · Evaluación del Error y Poda Asociativa (Circuit Breaker)
Anti-bucle infinito · Poda de hipótesis

Si los tests fallan y $k < k_{\max}$, se registra la relación contradicts: esa hipótesis queda podada del espacio de búsqueda para la siguiente vuelta. Si $k = k_{\max}$, el disyuntor aborta inmediatamente, registrando el episodio fallido para evitar que futuras sesiones tropiecen con la misma piedra.

Fase 4 · Validación Cruzada y Consolidación Epistémica
Rol: Revisor Independiente + Curador de Memoria

Un revisor independiente audita el parche para descartar sobreajuste o trampas. Una vez aprobado, se actualiza el MemoryGraph conectando: Síntoma -[caused_by]-> Causa -[solved_by]-> Solución.

Fase 5 · Madurez y Promoción a Skill
Resultado: k → 1 (Paso único determinista)

Si una solución resuelve con éxito $\ge 3$ instancias análogas sin contradicciones, se promueve a Skill procedimental (promoted_to_skill). El issue se cierra en GitHub Projects con verificación confirmada.

4. La Taxonomía de Distancias Causales (L0 a L5) y el Dilema NRNE

Por qué el RAG vectorial clásico colapsa y por qué la activación en grafo de ALL es necesaria:

Nivel Distancia Manifestación del Error Comportamiento de RAG Vectorial Solución con ALL (MemoryGraph)
L0 Exacta Misma traza sintáctica y texto idéntico. Acierta por pura coincidencia léxica. Recuperación directa inmediata.
L1 Paráfrasis Mismo error con redacción léxica diferente. Acierta por similitud semántica. Embeddings semánticos locales.
L2 Semántica Conceptos afines en la misma tecnología. Acierto moderado con ruido. Activación directa entre nodos tecnológicos.
L3 Causal Síntomas completamente distintos con la misma causa raíz (Ej: timeout en test vs ECONNREFUSED en socket). COLAPSO TOTAL (NRNE): Coseno cercano a 0. Concluye que no hay solución previa. Activación Propagada: Salta de síntoma a causa raíz compartida mediante aristas caused_by.
L4 Multi-salto Deducción a través de varios módulos o middlewares. Incapaz de encadenar relaciones. Camino asociativo multi-arista en el grafo.
L5 Transferencia Patrón análogo entre ecosistemas distintos. Colapso absoluto por vocabulario disjunto. Skills abstractas desacopladas del lenguaje.

5. Métricas Científicas de Verificación

RFR → 0
Repeated Failure Rate

Fracción de fallos cuyas causas raíz ya eran conocidas en el historial. Mide la erradicación del tropiezo repetido.

LG > 0
Learning Gain

P(Éxito | Memoria ALL) − P(Éxito | Sin memoria). Incremento neto medido con recibos inmutables.

k → 1
Convergencia de Skill

Transición de iteraciones múltiples a ejecución determinista de paso único sin gasto de tokens.
